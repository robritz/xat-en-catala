# 03 — Cloud resources and the weights image

**What to build:** Everything the Cloud Run **model host** is assembled from, short of the host itself. A bootstrap script creates the cloud resources in the existing project, and a weights image holding the quantised model sits in the registry, ready to be copied from.

The weights are the Q6_K quantisation of `BSC-LT/salamandra-7b-instruct-2606`, 6.38 GB, from `mradermacher/salamandra-7b-instruct-2606-GGUF` at revision `8bcd7d8d8545749ef73b3046f7cb5cd64d8c70c1`. They are mirrored once into a bucket in the project so that no build depends on Hugging Face. The weights image holds only that file and is rebuilt only when the weights change.

See `docs/specs/model-host-cloud-run.md`, sections "Engine and weights", "Images" and "Provisioning", and `docs/adr/0001-quantised-llama-cpp-on-cloud-run.md`. The region is `europe-west4`. `gcloud` is installed outside the default shell path, in the owner's home directory, and is signed in with the project set.

**Needs the owner:** The script creates billable resources. Show it to the owner and wait for a go before running it. Approval given earlier, for anything else, does not count.

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] A bootstrap script in the model directory creates: a Docker repository in Artifact Registry; a bucket; a service account for the service and one for the pipeline, each with only the roles it needs; and a secret in Secret Manager holding a freshly generated API key.
- [ ] The script is safe to run again: a second run changes nothing and exits cleanly.
- [ ] The script takes the project and region from variables at its top, and does not create build triggers, which belong to ticket 06.
- [ ] The API key is generated by the script and never printed, committed or echoed to a log.
- [ ] The weights file is fetched at the pinned revision, its SHA-256 is checked against a value recorded in the repository, and it is stored in the bucket. A file that fails the check is not stored.
- [ ] A build configuration for the weights image reads the file from the bucket and pushes an image that holds it and nothing else. It is run by hand, not on merge.
- [ ] The weights image is in the registry, tagged so that the quantisation and revision it holds can be read from the tag.
- [ ] The service's account can read the key secret, and the pipeline's account can push images and deploy the service. Neither is the default compute service account.
- [ ] The README says what the script creates and how to run it.
